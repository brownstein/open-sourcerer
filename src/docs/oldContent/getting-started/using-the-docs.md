# Using the Docs & Editor

The **Docs tab** is your spellcraft companion: every lesson, API reference, and troubleshooting tip lives here. Pair it with the **Code Editor** to iterate quickly—read a concept, paste a snippet, tweak, and observe the results in-game. This guide walks you through the workflow.

---

## 1. Navigating the Docs Tab

### Sidebar Controls

- **Hide Index** – collapses the sidebar when you need more screen real estate.
- **Search Placeholder** – future updates will let you jump directly to definitions; for now, explore via the collapsible sections below.
- **Expandable Sections** – five primary categories (Getting Started, Core JavaScript, Spell APIs, Gameplay Integrations, Reference & Glossary) each contain focused subtopics. Click a header to expand or collapse it.

### Content Panel

- Markdown content renders with headers, callouts, and code blocks.
- Internal links use anchors (for example, `[#syntax-and-variables](#syntax-and-variables)`) to move you between pages.
- Code samples feature the **Try in code editor** button when experimentation is encouraged.

Pro tip: keep the Docs tab open while playing and use the dock to switch between Docs, Editor, and Console quickly.

---

## 2. Working in the Code Editor

| Feature | Shortcut / Tip |
| --- | --- |
| **Run Spell** | Click _Run_ or press `Ctrl + Enter` / `Cmd + Enter` to execute the current script. |
| **Console Output** | Check the Console tab for `console.log`, warnings, and errors—mirrors standard JavaScript Console behavior. |
| **Spell Library** | Save versions as spells to track iterations or share them. Use descriptive names like `FirePulse.v2`. |
| **Linting Feedback** | Inline hints flag syntax issues; hover to see suggestions. |

Combine these tools: load a docs example, modify parameters, re-run, and watch the Dreamscape respond instantly.

---

## 3. Spell-Building Workflow

1. **Discover** – Read the relevant documentation page (e.g., “Fire Spell API”).
2. **Prototype** – Copy the boilerplate example into the Code Editor.
3. **Experiment** – Adjust values, add conditions, or integrate with gameplay events.
4. **Validate** – Run the spell, observe enemy behavior, and review console output.
5. **Refine** – Log key variables, test edge cases, and optimize performance.
6. **Document** – Add comments inside your script or reference the Glossary for shared terminology.

By repeating this loop, you’ll build a personal spell arsenal while mastering real JavaScript patterns.

---

## 4. Tips for Efficient Learning

- **Bookmark favorites** – Pin frequently used pages (like control flow or spell hooks) in your browser.
- **Pair coding with story quests** – Each quest introduces a mechanic the docs expand on. Alternate between them for context.
- **Keep a debug journal** – Track what changes you made and the outcomes. This makes troubleshooting faster later.
- **Embrace small iterations** – Focus on modifying one behavior at a time; you’ll learn faster and avoid messy bugs.
