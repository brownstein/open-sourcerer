# Open Sourcerer
A metroidvania where you write your own spells in JavaScript.

Open Sourcerer is a 2D side-scroller built with React, Three.js and Vite.
Players unlock spell modules and compose them into scripts that run in a
sandboxed web worker, then cast those scripts in combat and puzzles.

## Getting started

Requires a recent Node.js (developed on Node 24).

```sh
npm i && npm run prestart && npm start
```

`prestart` compiles the helper scripts in `scripts/ts` and regenerates the
spell-module RPC bindings (see [Spell scripting](#spell-scripting)). Vite then
serves the game at http://localhost:5173.

To make a production build:

```sh
npm run build
```

## What a spell looks like

Spells are plain JavaScript. Game capabilities come in through `require`:

```js
// Pull in module dependencies.
const fire = require("fire");

// Cast an aimed fireball every time the player clicks.
while (true) {
  new fire({ aim: true });
}
```

The built-in spells in `src/scripting/builtinScripts/raw/*.raw.js` are good
examples to read.

## Project layout

| Path | What lives there |
| --- | --- |
| `src/engine` | Core engine: rendering, camera, physics glue, loaders, scheduling, sound, Spine animation (`engine/spine`) |
| `src/api` | Engine-facing API surface used by entities and levels (entities, levels, spells, quests, controls, …) |
| `src/entities` | Everything that lives in a level: player, enemies and bosses, NPCs, items, spells, terrain, runes |
| `src/levels` | Level definitions (`levels/`) and Tiled maps and tilesets (`tiled/`, `tilesets/`) |
| `src/scripting` | The spell runtime: worker sandbox, spell modules, built-in scripts, runic layer |
| `src/challenges` | Coding challenges and their grading |
| `src/multiplayer` | Yjs-based replication, lobby and match logic, with Trystero (P2P) and Steam transports |
| `src/docs` | In-game documentation, written in MDX (`docs/content/en`) |
| `src/i18n` | i18next setup and locale files |
| `src/ui`, `src/components`, `src/redux` | React UI and app state |
| `scripts/ts` | Developer tooling (see below) |

### Spell scripting

Spell code runs in a **web worker**. Anything that touches the game world
(the level, Three.js, entities, physics) runs on the **main thread**. Each
spell module is a pair of files in `src/scripting/modules/auto/`:

- `<Name>.pseudo.ts`: what `require("<name>")` returns inside spell code,
  running in the worker.
- `<Name>.native.ts`: the privileged main-thread handler that changes the world.

The RPC glue between the two (`autoNativeBindings.ts`, `autoPseudoBindings.ts`)
is generated by `npm run generate-auto-module-bindings`, which runs as part of
`prestart` and `prebuild`. Don't edit the generated files by hand.

[`src/scripting/MODULE_PATTERNS.md`](src/scripting/MODULE_PATTERNS.md) is the
detailed guide to writing or debugging a module.

## Developer scripts

Every script compiles `scripts/ts` first, then runs its tool.

| Command | What it does |
| --- | --- |
| `npm run generate-auto-module-bindings` | Regenerates the worker/main-thread bindings for spell modules |
| `npm run generate-builtin-script-metadata` | Writes metadata and icons for new built-in `*.raw.js` spells |
| `npm run generate-spell-apis` | Emits a `.d.ts` describing the full spell module API |
| `npm run generate-level` | Builds a Tiled level from ASCII art piped on stdin (see the header of `scripts/ts/generate-level.ts`) |
| `npm run tileset-editor` | Terminal UI for classifying tiles and generating collision data for Tiled tilesets |
| `npm run screenshot-levels` | Captures a PNG of each level through the running dev server |
| `npm run trace-spine-regions` | Traces Spine atlas regions into collision polygons |
| `npm run document` | Generates entity documentation |

## Contributing

1. Fork the repo and create a branch.
2. Run the game locally with the steps above.
3. Check that it typechecks: `npx tsc --noEmit -p .` (Vite also reports type
   errors in the dev server overlay).
4. Open a pull request describing what you changed and how you tested it.

## Story
The game's story was primarily focused on exploring the history of
Ecma 6, a futuristic space colony turned post-civilization fantasy
where ancient nanotechnology was revered as magic.

The basic gist was that people came to the planet, developed advanced
AI and magic-like technology, became over-reliant, and gradually forgot
how everything worked. A cataclysmic service interruption (war) triggered
a social collapse that ended with people drawing desktop icons in the sand
to summon cooking fires. Subsequent generations lost the connection between
programming and user-interface, until point and click became a vacuous
swish and flick.

There was also a sub-plot (producing the main antagonist) of a
consciousness-upload system for the dead where "spirits" could
trade their compute resources, and which gradually succumbed to
zero-sum-game capitalism where one controlling CEO, who had
added a 1% minimum fiscal growth rate for himself as a prime directive
on upload, ate the compute of the majority of the upload population
and turned the system into a cage for himself. Desperate to break
into physical reality, the antagonist Aeon was intended as a final boss.

### Dev Story
This started as a side project in 2018, was encapsulated into a part-time
commercial venture in 2022, and failed after a 2026 full time pivot with
a 10 person team. We tried adding vibe coding towards the end and quality
slopped.

Learn from our mistakes.
